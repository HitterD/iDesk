MASALAH 3 — ReminderSettingsPanel: Memory Leak (no AbortController)
❌ Saat Ini
useEffect(() => {
  api.get('/notifications/preferences')
    .then(r => setCurrent(r.data.reminderIntensity));
  // No cleanup! setState setelah unmount
}, []);
✅ Setelah Perbaikan
useEffect(() => {
  const ctrl = new AbortController();
  api.get('/notifications/preferences', { signal: ctrl.signal })
    .then(r => setCurrent(r.data?.reminderIntensity));
  return () => ctrl.abort();
}, []);
MASALAH 4 — useActionItems: staleTime hilang
❌ Saat Ini
useQuery({
  queryKey: ['action-items'],
  queryFn: () => api.get(...),
  refetchInterval: 60000,
  // staleTime tidak ada
  // → fresh fetch tiap mount komponen
});
✅ Setelah Perbaikan
useQuery({
  queryKey: ['action-items'],
  queryFn: () => api.get(...),
  refetchInterval: 60000,
  staleTime: 30_000, // 30s
  gcTime: 120_000, // 2m
});
Pilih Pendekatan Implementasi
A

Fix Bertahap (Recommended)

P0/P1 backend dulu → P1 frontend → P2 performance. Setiap fix di-commit terpisah. Lebih aman, mudah review.

B

Fix Semua Sekaligus

Satu commit besar mencakup semua perbaikan backend + frontend. Lebih cepat tapi harder to review/rollback.

C

Backend Only Dulu

Fokus ke backend fixes (SQL N+1, dead code, type safety) dahulu. Frontend di iterasi berikutnya.
